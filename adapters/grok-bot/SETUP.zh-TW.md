# 手把手：請既有的 bot 建立 Token 顧問

[English](SETUP.en.md) · **繁體中文**

建立 Token 顧問有三種方式：用分享的範本、請主 bot 建立、或自己用 repo 建立（三種都在 [README 的快速開始](../../README.zh-TW.md#快速開始)）。這份教學詳細說明第二種，也就是 Grok Bot 最常見的做法：每一句要說的話都寫好了，照著複製貼上即可，大約 10 分鐘。步驟 2 的檢查與步驟 3 的驗收，三種方式都適用。顧問建好之後會自己查各 bot 的設定，所以你只需要告訴它目標。

| 步驟 | 對誰說 | 做什麼 |
|---|---|---|
| 1 | 既有的 bot（下稱「主 bot」） | 建立 Token 顧問：工作區、指令、權限 |
| 2 | 主 bot | 確認指令是全文、沒有被改寫 |
| 3 | Token 顧問 | 驗收：用範例資料試一次 |
| 4 | Token 顧問 | 第一次正式使用：上傳你的用量匯出檔 |
| 5 | 兩者 | 之後的用法與更新 |

> **開始前：** 請在主 bot 那裡**開一個新的 chat** 再說下面的話。建立顧問的對話很長，放進主 bot 平常那個長長的 chat，之後它每次被叫醒都要重讀這段，正是這個專案要幫你省的錢。

---

## 步驟 1：請主 bot 建立 Token 顧問

把下面整段貼給主 bot：

```text
請幫我建立一個新的 bot，規格如下，全部照做，不要自行增減或「優化」：

1. 名稱：Token 顧問
2. 用途：只在我直接呼叫時，分析 bot 團隊的 token 花費並給建議。
3. 工作區：把 https://github.com/EndeavorYen/bot-token-optimizer clone 到它的工作區，資料夾名稱保持 bot-token-optimizer。它需要能在這個資料夾裡執行 python3。
4. 指令：把 repo 裡 adapters/grok-bot/ADVISOR_BOT.zh-TW.md 的「全文」原封不動設為它的指令。不要摘要、不要改寫、不要翻譯、不要刪段落、不要加上你自己的規則。
5. 喚醒方式：不要把它加進任何群組，不要設排程或自動化，不要讓它訂閱任何通知。它只在我直接傳訊息給它時才被喚醒。
6. 權限：它需要能「讀取」所有 bot 的設定（名稱、指令、排程與自動化、所在群組、對話長度），這樣它才能自己調查，不用回頭問我。它不需要、也不應該有修改其他 bot 的權限。

完成後只回報這五件事，不用其他說明：
(a) bot 名稱
(b) 指令的第一行
(c) 指令中最後一個「## 」開頭的標題
(d) clone 是否成功，以及在工作區執行 python3 core/cli.py --version 的結果
(e) 它能不能讀到其他 bot 的設定（能／不能）
```

**為什麼要這樣寫：**
- **「原封不動」**：bot 很喜歡把長指令「整理」成重點，但顧問的工作方法、數字規則、範例都在細節裡，被摘要後就會變回「要什麼給什麼」。
- **能讀、不能改**：顧問要自己去查每個 bot 的排程、指令和群組，才能給你「把 X 從每 30 分鐘改成每 2 小時」這種具體建議，而不是反過來問你。但它只提建議，變更由主 bot 在你同意後執行。
- **不進群組、不設排程**：群組裡每一則訊息都會叫醒成員、讓它重讀整段上下文。顧問平常不該花任何 token。
- **只回報五件事**：讓主 bot 這段對話保持短。

## 步驟 2：確認主 bot 回報的內容

正確的回報應該長這樣：

| 項目 | 應該是 |
|---|---|
| (a) 名稱 | Token 顧問 |
| (b) 第一行 | `# Token 成本顧問（Grok Bot 版）— 工作手冊` |
| (c) 最後一個標題 | `## 基本守則` |
| (d) 版本 | `bto` 加上和 [README](../../README.zh-TW.md) 最上方版本徽章相同的版本號 |
| (e) 讀取其他 bot | 能 |

**對不上時，貼給主 bot：**

- 第一行或最後一個標題不對（指令被摘要或截斷了）：

  ```text
  Token 顧問的指令不是全文。請重新讀取 repo 裡 adapters/grok-bot/ADVISOR_BOT.zh-TW.md，把整份檔案一字不改地設為它的指令，取代目前的內容。完成後再回報第一行和最後一個「## 」標題。
  ```

- (e) 是「不能」（平台不開放讀取其他 bot）：改由主 bot 定期把設定盤點成檔案放進顧問的工作區。現在先做一次：

  ```text
  請把下列資料寫進 Token 顧問工作區的 inventory.md，不要修改任何設定：每個 bot 的名稱、完整指令、所有排程或自動化（間隔或時間、運作時段、時區）、所在的群組、會通知哪些 bot 以及大約頻率、目前的對話長度（看得到的話）。完成後只回覆「完成」。
  ```

  之後 bot 有變動時，再貼一次同一段即可。

- clone 失敗（主 bot 讀不到 GitHub）：請自己到 GitHub 頁面點 **Code → Download ZIP**，把 zip 上傳給主 bot，並說：

  ```text
  這是 bot-token-optimizer 的 zip。請解壓到 Token 顧問的工作區（資料夾名稱 bot-token-optimizer），指令改用壓縮檔裡 adapters/grok-bot/ADVISOR_BOT.zh-TW.md 的全文，原封不動。
  ```

- `--version` 執行失敗（顧問不能跑程式）：

  ```text
  Token 顧問需要能在工作區執行 python3（只用標準函式庫，不用安裝套件）。請幫它開啟執行程式的能力，然後再執行一次 python3 core/cli.py --version 並回報結果。
  ```

## 步驟 3：驗收，用範例資料試一次

**開一個和 Token 顧問的新 chat**，貼上：

```text
我們先試一次。請在你的工作區執行 python3 samples/make_grok_export.py 產生一份範例的用量匯出檔，把它當成我的資料；這些 bot 的排程在 samples/grok_schedules.txt，就當作是你從各 bot 設定查到的。我的時區是 +08:00。目前額度大約 3 天就用完，我希望撐滿 7 天。請給我你的建議。
```

**好的回答會有這些特徵**（數字來自範例資料，每次都一樣）：

- 第一段就是結論：每週約 **$158**，要撐滿 7 天得降到約 **$68**；**一半的花費來自 monitor 這個 bot**（每 30 分鐘醒來一次、每次重讀約 11 萬 token、**64%** 的檢查無事可做）。
- 第一項建議是具體的變更：**monitor 從每 30 分鐘改成每 2 小時**，每週省約 **$41–59**。
- 有一張前幾項變更的表格，每項附金額和把握；合計約 **每週 $72–119**，額度約可撐 **5.5–12 天**，並說明剩下的落差在哪裡、它接下來要怎麼查。
- 不會放棄交接：每個 bot 有各自的門檻（monitor 和 digest 4 萬 token、其他 10 萬），每個每天最多約一次。
- 附上一則**可以直接貼給主 bot 的變更請求**，並問你要不要送出。
- 最多問你**一個**問題，而且是只有你能回答的（例如「事故晚 2 小時才發現可以接受嗎？」）。

**出現下面任何一項，就是沒照指令走：**

| 紅旗 | 代表什麼 |
|---|---|
| 問你「有哪些 bot」「誰最常被叫醒」「排程是什麼」 | 把自己查得到的事丟回給你 |
| 「找出最常被叫醒的 bot」「考慮減少喚醒」這類建議 | 給原則，沒有給具體變更 |
| 同一件事拆成兩項（例如「別超過 20 萬」和「6 萬就交接」） | 重複計算 |
| 前後數字對不起來（例如「撐 4.3 天」和「4–6 天」），或因為某個設定不可行就放棄整個槓桿 | 心算，沒有用工具 |
| 「測試通過 78/78」、檔案路徑、指令、PASS/FAIL | 把內部作業講給你聽 |
| 「你要 A、B 還是 C？」 | 給選單，沒有給建議 |
| 每則訊息結尾都叫你開新 chat | 制式提醒重複 |

有紅旗時，先對 Token 顧問說一次：

```text
請重新讀一次你的指令，特別是「讓你成為顧問的兩條規則」和「現場調查」兩節，然後照那個方式重新回答剛才的問題。
```

還是一樣的話，問題多半出在指令被改寫過或是舊版，回到步驟 2，請主 bot 重新設定全文。

## 步驟 4：第一次正式使用

1. 從 Grok Bot 的用量頁面匯出 **usage events** CSV（欄位開頭是 `Date, Cloud Agent ID, Automation ID, …`；介面名稱可能略有不同）。期間選**最近 7 天**最好；少於 2 天的話，趨勢會不準。匯出時記下用量頁面上的額度剩餘百分比和重置時間，跟檔案一起附上。
2. 開一個和 Token 顧問的**新 chat**，附上檔案並貼上（把空格填好，不知道的可以刪掉）：

   ```text
   附件是最近 7 天的用量匯出檔。我的時區是 +08:00。
   目標：每週控制在 $____（或：額度要撐滿 7 天）。
   不能動的：____（例如：主 bot 一定要留、回覆不能變慢）。
   請給我結論和一頁式備忘錄。
   ```

3. 它會先自己去查各 bot 的排程、指令和群組，再給你結論、具體變更和一頁式備忘錄。它問你的問題只會是目標、限制或取捨（例如「事故晚 2 小時才發現可以接受嗎？」）。
4. 看過變更請求、覺得可以，就回它「送出」；它會交給主 bot 執行。也可以只挑其中幾項，或自己貼給主 bot。

## 步驟 5：之後的用法

都是對 Token 顧問說，每次諮詢開一個新的 chat。

**想檢視組織時：**

```text
組織能不能更精簡？告訴我誰是冗員、哪些 bot 該合併或拆開，並給我最佳的組織圖。這些一定要保留：____（可不填）。
```

它會自己去讀誰通知誰，用量到的上下文建立團隊模型，然後回覆：哪些是冗員、合併與拆分及各自省多少、目前與建議的組織圖，以及變更請求。

**理論問題：**

```text
主 bot 目前上下文大約 ____ token，一天被叫醒約 __ 次。現在交接到新 chat 划算嗎？
```

**改完一週後驗證**（用和上次相同的期間長度匯出）：

```text
附件是改完之後最近 7 天的用量匯出檔。請和上次的備忘錄做同期比較，告訴我 KPI 達成了沒有、下一步做什麼。
```

**repo 有新版時：**

- 更新工具，對 **Token 顧問**說：

  ```text
  請在你的工作區對 bot-token-optimizer 執行 git pull，然後回報 python3 core/cli.py --version 的結果。
  ```

- 如果新版改了 `ADVISOR_BOT.zh-TW.md`，再對**主 bot**說：

  ```text
  請把 Token 顧問的指令更新成它工作區裡 bot-token-optimizer/adapters/grok-bot/ADVISOR_BOT.zh-TW.md 的最新全文，一字不改，取代舊內容。完成後回報第一行和最後一個「## 」標題。
  ```

## 常見問題

**Token 顧問好像常常被叫醒、自己也在花錢？**
請主 bot 列出 Token 顧問所在的群組、排程和自動化，全部移除。它應該只在你傳訊息給它時才醒。

**可以把 Token 顧問加進大家的群組，讓它隨時看著嗎？**
不建議。群組裡每一則訊息都會讓它重讀整段上下文，等於花錢請顧問全天旁聽。需要時再把匯出檔丟給它，效果一樣，花費趨近於零。

**它說「Automation ID 是空的，只能依模型分組」是什麼意思？**
Grok Bot 的匯出檔通常分不出是哪個 bot 花的錢，只看得出用了哪個模型（例如 `grok-bot-default`）。顧問會自己拆開這一組：排程 bot 會在固定時間醒來，所以把每個 bot 的排程和匯出檔裡的喚醒時間對起來，就知道是誰。剩下的是你自己的訊息和 bot 之間的通知，它會依「誰通知誰」再拆開。

**美元數字是真的帳單嗎？**
方案內計費（匯出顯示 Included／Free）時不是。那是依 token 換算的等值，用來比較方案、當作額度消耗的指標。

**可以用英文版嗎？**
可以。步驟 1 改用 `ADVISOR_BOT.en.md`，步驟 2 的第一行和最後一個標題改成 `# Token Cost Advisor (Grok Bot) — playbook` 和 `## Ground rules`。英文版教學見 [SETUP.en.md](SETUP.en.md)。
